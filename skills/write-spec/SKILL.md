# Спецификация

Вход: решения разговора, выбранный подход, существующий документ. Проверь текущий код, словарь проекта и применимые ADR. Синтезируй известное; существенные пробелы отметь как открытые вопросы, не выдавая предположение за принятое решение.

Состав документа:
- Проблема и ожидаемое поведение для пользователя.
- Объём и исключения; необходимые сценарии, ошибки и граничные случаи.
- Существующие, изменяемые и новые модули: ответственность, взаимодействия, входы, результаты, ошибки и существенные инварианты.
- Принятые решения и компромиссы. Пути и короткие фрагменты допустимы, когда точнее фиксируют решение; результат прототипа пометь как источник решения.
- Проверяемые критерии приёмки, границы тестирования и подходящие проверки. Предпочитай существующие публичные интерфейсы.
- Нерешённые вопросы, если остались.

По умолчанию сохрани спецификацию в `.scratch/<тема>/spec.md`. Если пользователь указал другой путь или уже есть документ этой задачи, используй его. Для маленькой задачи достаточно краткого раздела в существующем плане. Не раздувай список сценариев ради полноты шаблона.

Результат готов, когда каждое известное требование отражено и проверяемо, а неизвестное обозначено. Написанная спецификация не означает согласие на реализацию. В design-plan верни документ для общего согласования; самостоятельный вызов завершай ссылкой и перечнем открытых вопросов. Трекер и публикация нужны только по запросу.

# Проверка дефектов

1. Используй переданный снимок и объём; если их нет, зафиксируй объём по [контракту изменений](../review-changes/CHANGES.md). Прочитай diff, окружающий код и доступные результаты проверок.
2. Ищи дефекты, внесённые изменениями: ошибки логики, уязвимости, существенное ухудшение производительности. Проверь объявления, импорты и обработку в полном контексте: отсутствие в diff не доказывает отсутствие в проекте.
3. Каждое замечание подкрепи сценарием: условие → ошибочное поведение → последствия. Укажи файл и строки новой версии, серьёзность и направление исправления. При возможной потере данных или уязвимости отдельно сообщи о неподтверждённом риске и назови недостающие доказательства.
4. При повторной проверке сохрани формулировки оставшихся замечаний, обновив расположение. Исправленные возвращай при повторном появлении; отклонённые — при новых доказательствах.

Выдай замечания по серьёзности и итог: существенных проблем не найдено / нужна дополнительная проверка / нужны исправления. Пустой список допустим. Отдельно назови пробелы проверки. Наличие тестов не означает их запуск; зелёный общий статус CI не отменяет пропуски и отдельные сбои.

Проверки документированных правил и требований выполняют review-standards и review-spec. В этом проходе код не меняй и комментарии не публикуй.

Источник методики: [PR-Agent /review](https://github.com/The-PR-Agent/pr-agent/blob/1fa93c85b64065d8944e6ac612605e4a27212361/pr_agent/settings/pr_reviewer_prompts.toml).

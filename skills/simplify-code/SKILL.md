# Упрощение кода

Вход: конкретные файлы либо изменения по [общему контракту](../review-changes/CHANGES.md). При вызове из review-changes работай только в режиме отчёта. Прямое поручение упростить код разрешает правки; просьба оценить — только предложения.

1. Прочитай код и его вызывающие места. Зафиксируй поведение, публичные интерфейсы и имеющиеся проверки.
2. Найди сложность, которую можно убрать: дублирование знания, ненужные уровни делегирования, параметры для гипотетических случаев, разнесённую по файлам логику одного изменения, повторяющиеся ветвления, запутанные имена и цепочки обращений. Это эвристики, а не нарушения стандарта; новая абстракция оправдана лишь если уменьшает общую сложность.
3. Для каждого предложения укажи место, конкретную пользу, сохраняемые инварианты и цену. Проверь существование полей, методов, сигнатур и импортов; если даёшь замену кода, она должна быть полной для выбранного фрагмента. Не предлагай уже сделанное или отклонённое без новых оснований.
4. При разрешённых правках внеси небольшие изменения и выполни проверки затронутого поведения. Изменение поведения или публичного контракта вынеси отдельно; это уже не упрощение с сохранением поведения.

Выдай только полезные предложения, начиная с важнейших, или отчёт о правках и проверках. Пустой список допустим. Дефекты передавай в review-bugs, не смешивая их с необязательными улучшениями.

Основа формата предложений: [PR-Agent /improve](https://github.com/The-PR-Agent/pr-agent/blob/1fa93c85b64065d8944e6ac612605e4a27212361/pr_agent/settings/code_suggestions/pr_code_suggestions_prompts.toml).

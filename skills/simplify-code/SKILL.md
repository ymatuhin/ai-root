# Упрощение кода

Вход: конкретные файлы либо изменения по [общему контракту](../review/CHANGES.md). При вызове из review работай только в режиме отчёта. Прямое поручение упростить код разрешает правки, которые сохраняют поведение и публичные контракты; просьба оценить — только предложения. Изменения логики, функционала или контрактов применяй только после подтверждения пользователя.

1. Прочитай код и его вызывающие места. Зафиксируй поведение, публичные контракты и имеющиеся проверки.
2. Найди сложность, которую стоит убрать:
   - **Без смены поведения и контрактов (код и тесты):** дублирование знания, ненужные уровни делегирования, параметры для гипотетических случаев, разнесённую по файлам логику одного изменения, повторяющиеся ветвления, запутанные имена, цепочки обращений; в тестах — проверки без логики, ассерты на внутренние вызовы моков или CSS-классы, дубли сценариев, уже закрытых на публичной границе модуля. Это эвристики, а не нарушения стандарта; новая абстракция оправдана лишь если уменьшает общую сложность.
   - **Через упрощение логики или функционала:** ветки, режимы, опции, тихие фолбэки, слои совместимости, особые случаи, состояния или API/UI-возможности, чья поддержка стоит несоразмерно дорого относительно пользы — когда отказ от них, объединение правил или замена на явную ошибку заметно упрощают код, модель данных или тесты.
3. Проверь каждое предложение по коду (вызывающие места, поля, методы, сигнатуры, импорты); уже сделанное и отклонённое без новых оснований пропусти:
   - **Без смены поведения:** место, конкретная польза, сохраняемые инварианты и цена; если даёшь замену кода, она должна быть полной для выбранного фрагмента.
   - **Упрощение логики или функционала:** место, какую сложность убирает (ветки, состояния, файлы, тесты), что меняется или исчезает в поведении, функционале или контракте, какие сценарии и вызывающие места затронет и что будет вместо этого (единое поведение, явная ошибка, ручной обход или отказ).
4. При разрешённых правках внеси небольшие изменения без смены поведения и выполни проверки затронутого поведения.

Выдай только полезные пункты, начиная с важнейших: отчёт о правках и проверках (или предложения без смены поведения в режиме отчёта) и, если есть стоящие идеи по упрощению логики или функционала, отдельный пронумерованный блок **«На обсуждение»**. Пустой список допустим. Дефекты отмечай по [review/BUGS.md](../review/BUGS.md), не смешивая их с упрощениями.

Основа формата предложений: [PR-Agent /improve](https://github.com/The-PR-Agent/pr-agent/blob/1fa93c85b64065d8944e6ac612605e4a27212361/pr_agent/settings/code_suggestions/pr_code_suggestions_prompts.toml).

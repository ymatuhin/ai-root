# Проверка дефектов

1. Используй переданный снимок и объём; если их нет, зафиксируй объём по [контракту изменений](CHANGES.md). Прочитай diff, окружающий код и доступные результаты проверок.
2. Ищи дефекты, внесённые изменениями: ошибки логики, уязвимости, существенное ухудшение производительности. Проверь объявления, импорты и обработку в полном контексте: отсутствие в diff не доказывает отсутствие в проекте.
3. Проверь каждое замечание сценарием: условие → ошибочное поведение → последствия. Запиши его сжато в 2–4 строки: файл проекта и строки новой версии, серьёзность, условие, эффект и направление исправления; подробную трассировку по зависимостям оставляй для спорных случаев или ответа на уточнение. При возможной потере данных или уязвимости отдельно сообщи о неподтверждённом риске и назови недостающие доказательства.
4. При повторной проверке сохрани формулировки оставшихся замечаний, обновив расположение. Исправленные возвращай при повторном появлении; отклонённые — при новых доказательствах.

Выдай замечания по серьёзности и итог: существенных проблем не найдено / нужна дополнительная проверка / нужны исправления. Пустой список допустим. Отдельно назови пробелы проверки.

Проверки документированных правил и требований описаны в [STANDARDS.md](STANDARDS.md) и [SPEC.md](SPEC.md). В этом проходе код не меняй и комментарии не публикуй.

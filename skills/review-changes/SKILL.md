# Ревью изменений

При повторной проверке используй список замечаний предыдущего раунда и [правила цикла](LOOP.md). Самостоятельный запрос на ревью остаётся одним раундом без исправлений.

1. Зафиксируй объём и состояние по [CHANGES.md](CHANGES.md). Прочитай применимые правила и найди источник требований. Если изменений нет, сообщи это и заверши.
2. Подключи [review-bugs](../review-bugs/SKILL.md), [review-standards](../review-standards/SKILL.md), [review-spec](../review-spec/SKILL.md) и [simplify-code](../simplify-code/SKILL.md) в режиме отчёта. Без требований пропусти review-spec с явной причиной; без кода упрощение кода неприменимо.
3. Независимые проходы можно поручить субагентам, когда это оправдано объёмом и они доступны. Иначе выполни их последовательно сам. Передай каждому одинаковый снимок, базу, список файлов, правила, требования и его методику. Исполнители читают одно состояние и не меняют файлы.
4. Проверь замечания по исходникам, объедини дубли, разреши противоречия по доказательствам. Неразрешённое противоречие обозначь явно. Присвой замечаниям постоянные ID и сохрани источник каждого; отдели дефекты и нарушения требований от необязательных улучшений.
5. Сообщи итог, замечания по серьёзности, пропущенные проходы и ограничения проверки. Укажи, какое состояние проверялось. Если оно изменилось во время ревью, повтори затронутые проверки на новом снимке перед окончательным выводом.

Запрос на ревью не разрешает правку кода или публикацию комментариев. Исправления выполняет вызывающий implement либо отдельное поручение пользователя.

# Ревью изменений

Самостоятельный запрос на ревью выполняй без исправлений. Для многораундовой проверки исправлений в полном режиме используй [правила цикла](LOOP.md).

Для небольшой локальной правки с ясными последствиями достаточно одного общего прохода по вопросам ниже без чтения вложенных методик и `LOOP.md`. Если изменение затрагивает безопасность, сохранность данных, конкурентное состояние или интерфейсы нескольких модулей, используй полный режим. При неясных последствиях сначала исследуй их; если неопределённость остаётся, выбери полный режим.

1. Зафиксируй объём и состояние по [CHANGES.md](CHANGES.md); если вызывающий передал готовый объём и исходно грязные посторонние файлы, сохрани эту границу. Прочитай применимые правила и найди источник требований. Если изменений нет, сообщи это и заверши.
2. Проверь весь согласованный объём: ошибки и их последствия, документированные правила, соответствие требованиям, неудачные новые имена, бесполезные или хрупкие тесты (проверки без логики, ассерты на внутренние вызовы моков/CSS-классы, дублирование покрытых на публичной границе сценариев — см. [tdd/tests.md](../tdd/tests.md)) и сложность, которую можно убрать без изменения поведения. Для небольшой правки выполни это одним проходом сам. В полном режиме подключи [BUGS.md](BUGS.md), [STANDARDS.md](STANDARDS.md), [SPEC.md](SPEC.md) и [simplify-code](../simplify-code/SKILL.md) в режиме отчёта (при новых или переименованных сущностях сверь их с [good-naming](../good-naming/SKILL.md)). Без требований пропусти их сравнение с явной причиной; без кода упрощение кода неприменимо.
3. В полном режиме при доступности субагентов по умолчанию поручи проверку одному независимому read-only субагенту в чистом контексте со всеми применимыми методиками; дели на отдельные параллельные проходы по методикам только на большом diff. Без субагентов выполни проходы последовательно сам. Передай одинаковый снимок, базу, список файлов задачи, исключённые исходные изменения, правила и требования. Исполнители читают одно состояние и не меняют файлы.
4. Проверь замечания по исходникам, объедини дубли, разреши противоречия по доказательствам. Для каждого укажи место, условие, последствия и основание; отдели дефекты и нарушения требований от необязательных улучшений. Неразрешённое противоречие обозначь явно.
5. Сообщи итог, существенные замечания и ограничения проверки. Укажи, какое состояние проверялось; в полном режиме перечисли пропущенные проходы. Если состояние изменилось во время ревью, повтори затронутые проверки на новом снимке перед окончательным выводом.

Самостоятельный запрос на ревью не разрешает правку кода. Исправления выполняет вызывающий implement либо отдельное поручение пользователя.

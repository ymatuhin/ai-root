# Ревью изменений

Самостоятельный запрос на ревью выполняй без исправлений. Для повторной проверки используй прежние замечания и [правила цикла](LOOP.md).

Для небольшой локальной правки с ясными последствиями достаточно одного общего прохода по применимым вопросам ниже. Если изменение затрагивает безопасность, сохранность данных, конкурентное состояние или интерфейсы нескольких модулей, используй полный режим. При неясных последствиях сначала исследуй их; если неопределённость остаётся, выбери полный режим.

1. Зафиксируй объём и состояние по [CHANGES.md](CHANGES.md). Прочитай применимые правила и найди источник требований. Если изменений нет, сообщи это и заверши.
2. Проверь весь согласованный объём: ошибки и их последствия, документированные правила, соответствие требованиям, сложность, которую можно убрать без изменения поведения. Для небольшой правки выполни это одним проходом сам; читать все отдельные методики не требуется. В полном режиме подключи [review-bugs](../review-bugs/SKILL.md), [review-standards](../review-standards/SKILL.md), [review-spec](../review-spec/SKILL.md) и [simplify-code](../simplify-code/SKILL.md) в режиме отчёта. Без требований пропусти их сравнение с явной причиной; без кода упрощение кода неприменимо.
3. В полном режиме независимые проходы можно поручить субагентам, когда это оправдано объёмом и они доступны. Иначе выполни их последовательно сам. Передай каждому одинаковый снимок, базу, список файлов, правила, требования и его методику. Исполнители читают одно состояние и не меняют файлы.
4. Проверь замечания по исходникам, объедини дубли, разреши противоречия по доказательствам. Для каждого укажи место, условие, последствия и основание; отдели дефекты и нарушения требований от необязательных улучшений. В полном режиме присвой замечаниям постоянные ID и сохрани источник каждого. Неразрешённое противоречие обозначь явно.
5. Сообщи итог, существенные замечания и ограничения проверки. Укажи, какое состояние проверялось; в полном режиме перечисли пропущенные проходы. Если состояние изменилось во время ревью, повтори затронутые проверки на новом снимке перед окончательным выводом.

Запрос на ревью не разрешает правку кода или публикацию комментариев. Исправления выполняет вызывающий implement либо отдельное поручение пользователя.

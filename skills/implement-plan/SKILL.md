# Выполнение плана

1. Прочитай согласованный план, спецификацию и задачи. Проверь критерии приёмки и зависимости. Если согласования нет, подготовь конкретный пакет через design-plan для согласования; существующее разрешение не запрашивай повторно.
2. Выбери готовые задачи: все их зависимости завершены. Передавай в [implement](../implement/SKILL.md) цель, границы файлов, интерфейсы, критерии, контекст и команду вернуть локальные проверки без полного ревью.
3. Выполняй задачи последовательно либо параллельно по зависимостям. Субагенты и отдельные worktree нужны при пользе и доступности; без них работай сам в текущей папке. Назначь владельцев общих файлов или выполняй конфликтующие задачи последовательно. Трекер, конкретный MCP, PR и коммиты не требуются.
4. Интегрируй результаты в общее состояние, проверь интерфейсы между задачами и приёмку плана. Незавершённая или упавшая задача не снимает блокировку зависимых. Конфликты разрешай с учётом обеих задач; изменение согласованного контракта верни на согласование.
5. На общем состоянии выполни [цикл ревью и исправлений](../review-changes/LOOP.md) через [review-changes](../review-changes/SKILL.md). Веди один бюджет раундов на интегрированный результат плана; не запускай полный набор ревью для каждой мелкой задачи.
6. Заверши по [правилам отчёта](../implement/REPORT.md). План завершён лишь при выполненной приёмке; блокировку назови явно.

Создание и публикация PR, изменение задач в трекере, коммиты и удаление веток выполняются по отдельному поручению, а не как автоматическое завершение.

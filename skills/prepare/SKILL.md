# План решения

Вход: выбранное направление, задача, готовый план для разбиения или вывод [explore](../explore/SKILL.md). Если направление уже согласовано, используй его без повторного выбора. Если пользователь попросил только оформить ТЗ/спецификацию или только разбить готовый план на задачи, выполни напрямую [SPEC.md](SPEC.md) или [SPLIT.md](SPLIT.md).

1. Сверь решение с кодом по собранным фактам; 2+ неизученных участка по умолчанию читай параллельными read-only субагентами (`путь:строки`, факты, пробелы), точечные пробелы дочитай сам. Выясни существенные неизвестные (поведение, ограничения, объём), предложив ответ по умолчанию с причиной; обычные детали решай сам. Интервью по запросу — [grilling](../grilling/SKILL.md); спорные термины и значимые компромиссы (ADR) — [domain-modeling](../domain-modeling/SKILL.md).
2. При выборе ответственности, интерфейсов и границ тестирования обратись к [codebase-design](../codebase-design/SKILL.md) (при существенных альтернативах интерфейсов — [методика сравнения](../codebase-design/INTERFACES.md)).
3. Через [doubt](../doubt/SKILL.md) проверь добавленную сложность. Если решение и факты из `explore` не изменились, новый проход не нужен.
4. Оформи требования по [SPEC.md](SPEC.md); при нескольких проверяемых частях или этапах разбей по [SPLIT.md](SPLIT.md).
5. Собери в `.scratch/YYYY-MM-DD-<тема>/` (переиспользуй существующую папку темы из `explore`) самодостаточный для новой сессии пакет: требования, задачи, краткую схему модулей и интерфейсов, объём, исключения и пути. Единый вход — `plan.md` (для одной задачи всё в нём; при разбиении сошлись на `spec.md` и `issues/`). Для маленькой задачи не плоди модули и файлы.

Пакет готов, когда существенные вопросы решены или отмечены блокирующими. Получи согласование до реализации (и при смене поведения, объёма, интерфейсов). Когда файлы записаны и блокирующих вопросов нет, выведи в конце отдельным блоком строку для новой сессии (с фактическим `./...` путём):

```text
/implement ./.scratch/YYYY-MM-DD-<тема>/plan.md
```

Для выполнения в текущей сессии после согласования используй [implement](../implement/SKILL.md).

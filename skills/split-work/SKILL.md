# Разбиение работы

Прочитай требования и текущий код; используй термины проекта. Неясные требования отметь до разбиения.

1. Выдели небольшие законченные изменения с самостоятельной проверкой. Предпочитай узкий путь через необходимые слои. Объединяй задачи одного модуля, если их нельзя проверить или выполнять отдельно.
2. Для широкого рефакторинга используй последовательность: добавить совместимую форму → перенести потребителей проверяемыми частями → удалить старую форму. Если части нельзя проверить отдельно, явно добавь общую задачу интеграции и не обещай зелёные проверки промежуточных состояний.
3. Для каждой задачи запиши идентификатор, результат, границы, зависимости по идентификаторам, критерии приёмки и проверки. Назови общие файлы или интерфейсы, мешающие безопасному параллельному выполнению.
4. Проверь отсутствие циклов и ссылок на неизвестные задачи, покрытие требований и порядок интеграции. Укажи задачи без зависимостей и возможные параллельные группы.

По умолчанию сохрани задачи разделом `.scratch/<тема>/plan.md`; если план уже существует, обнови его. При независимой передаче исполнителям используй отдельные файлы `.scratch/<тема>/issues/<NN>-<название>.md`, нумеруя их в порядке зависимостей. В design-plan верни разбиение в общий пакет, без отдельного обязательного согласования. Самостоятельный вызов завершай предложенным разбиением; это не разрешение на реализацию. Публикуй в трекер только по запросу, сохраняя зависимости; не закрывай родительскую задачу автоматически.

# Реализация задачи

По умолчанию работай как **оркестратор, экономящий основной контекст**: держи в нём только план или спецификацию, `git status`, `git diff --stat` и короткие сводки от субагентов; остальное делегируй субагентам. Для плана из 2+ задач читай [PLAN.md](PLAN.md).

**Прямой путь (без субагентов)** допустим только если:
1. Субагенты недоступны.
2. Это мелкая локальная правка 1–2 файлов не из `.scratch/` без изменения контрактов, рисков безопасности/данных/конкурентности и чтения других модулей.
3. Навык уже выполняется внутри субагента-исполнителя (вложенных субагентов не запускай).

## Шаги для одиночной задачи

1. **Контекст.** Зафиксируй критерии приёмки и `git status` (чужие грязные файлы сохрани и не правь); локального текста достаточно без трекера. Поиск по нескольким модулям или вызывающим местам поручи read-only субагенту (`факты`, `путь:строки`, `пробелы`), точечно дочитай сам.
2. **Реализация, имена и проверки.** Требования: минимальное достаточное изменение, предметные правила проекта, тесты и границы моков по [tdd/tests.md](../tdd/tests.md) и [tdd/mocking.md](../tdd/mocking.md) (полный [tdd](../tdd/SKILL.md) при test-first), перепроверка новых и переименованных идентификаторов по [good-naming](../good-naming/SKILL.md), проверки затронутого поведения и обязательные проверки проекта.
   - **Оркестратор:** поручи шаг одному пишущему субагенту-исполнителю (без вложенных субагентов), передав цель, пути к плану/спецификации, границы файлов, интерфейсы, критерии приёмки, чужие грязные файлы и требования выше; запроси короткий итог (`файлы`, `результат`, `проверки`, `ограничения`).
   - **Прямой путь:** выполни шаг сам.
3. **Ревью:**
   - **Быстрый путь (мелкая локальная правка из п. 2 исключений):** сверь diff в контексте (ошибки, граничные случаи, правила, требования, лишняя сложность; в тестах — тавтологии, ассерты на моки/детали реализации и дубли между слоями); при правках повтори проверки. `review`, `CHANGES.md`, `LOOP.md` и `REPORT.md` не открывай.
   - **Полный путь (всё остальное, включая любой план из `.scratch/`):** выполни [review](../review/SKILL.md) и [LOOP.md](../review/LOOP.md), поручив ревью свежему read-only субагенту с границами поручения, чужими грязными файлами, требованиями и результатами проверок. Для отдельной задачи многозадачного плана до интеграции ревью не запускай.
4. **Отчёт.** Быстрый путь: проблема и эффект, файлы, проверки, ограничения. Полный путь или запрос PR: по [REPORT.md](REPORT.md). Ответ субагента-исполнителя оркестратору (или часть плана): файлы, результат, проверки, ограничения.

Готово, когда критерии приёмки, проверки и ревью закрыты, а отчёт совпадает с diff. Существенные изменения согласованного поведения, объёма или интерфейсов верни на согласование.

# Выполнение плана

Дополнение к [implement](SKILL.md) для плана из нескольких задач.

1. Прочитай план, спецификацию и задачи. Проверь критерии приёмки, зависимости и разрешение на выполнение. Если существенные решения ещё не согласованы, подготовь конкретный пакет через design-plan; существующее разрешение используй без повторного запроса.
2. Выбери задачи, все зависимости которых завершены. Для каждой выполни шаги 1–3 из implement. При передаче исполнителю укажи цель, границы файлов, интерфейсы, критерии, контекст и необходимость вернуть локальные проверки без полного ревью.
3. Выполняй задачи последовательно либо параллельно по зависимостям. Субагенты и отдельные worktree нужны при пользе и доступности; без них работай сам в текущей папке. Назначь владельцев общих файлов или выполняй конфликтующие задачи последовательно.
4. Интегрируй результаты, проверь интерфейсы между задачами и приёмку плана. Незавершённая или упавшая задача сохраняет блокировку зависимых. Конфликты разрешай с учётом обеих задач; изменение согласованного контракта верни на согласование.
5. На общем результате выполни шаги 4–5 из implement: ревью, исправления и итоговый отчёт. Выбирай режим ревью по всему изменению; в полном режиме веди один бюджет раундов на результат плана. Полный набор ревью для каждой мелкой задачи не нужен.

План завершён при выполненной приёмке; блокировку назови явно. Трекер, конкретный MCP, PR и коммиты не требуются. Для публикации, изменения задач в трекере, коммитов и удаления веток нужно соответствующее поручение.

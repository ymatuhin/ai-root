# Выполнение плана

Дополнение к [implement](SKILL.md) для 2+ задач: работай как оркестратор, не загружая исходники в основной контекст.

1. Читай только план, спецификацию, задачи и `git status`. Прямой запуск с путём к плану означает разрешение на выполнение, если нет открытых блокирующих вопросов; иначе подготовь пакет через [prepare](../prepare/SKILL.md).
2. Готовые задачи (зависимости закрыты) по умолчанию отдавай отдельным субагентам-исполнителям (без вложенных) на шаг 2 из [implement](SKILL.md) без общего ревью, передавая контекст задачи и запрашивая короткий отчёт из [implement](SKILL.md).
3. Непересекающиеся файлы запускай параллельно в текущей папке; общие файлы или зависимости — последовательно, но в отдельных субагентах. Ветки и `worktree` — только по явному поручению пользователя (тогда вложи контекст `.scratch/` прямо в задание, так как `.scratch/` в `worktree` не копируется). Без субагентов выполняй последовательно сам.
4. Интегрируй результаты, проверь стыки и приёмку плана; исходники читай точечно при конфликтах и интеграции. Упавшая задача блокирует зависимые; смена согласованного контракта — на согласование.
5. Итоговое ревью на общем результате проведи в read-only субагенте по [review](../review/SKILL.md) и одному циклу [LOOP.md](../review/LOOP.md); заверши по [REPORT.md](REPORT.md).

План завершён при выполненной приёмке; блокировку назови явно.

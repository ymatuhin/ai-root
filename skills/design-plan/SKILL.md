# План решения

Вход: выбранное направление, задача или вывод explore. Если направление уже согласовано, используй его без повторного выбора.

1. Сверь решение с кодом, опираясь на уже собранные в разговоре факты и дочитывая исходники только по пробелам. Выясни существенные неизвестные в поведении, ограничениях и объёме; для каждого вопроса предложи ответ по умолчанию с причиной. Факты собери сам, используй уже согласованные ответы, обычные технические детали решай самостоятельно. Подробное интервью через [grilling](../grilling/SKILL.md) проводи по запросу пользователя. Через [domain-modeling](../domain-modeling/SKILL.md) уточняй термины при неоднозначности. Значимый принятый компромисс фиксируй ADR по его правилам.
2. При выборе ответственности, интерфейсов и границ тестирования обратись к справочнику [codebase-design](../codebase-design/SKILL.md). При существенных альтернативных интерфейсах используй его [методику сравнения](../codebase-design/INTERFACES.md).
3. Через [doubt](../doubt/SKILL.md) проверь добавленную сложность. Используй предыдущий результат explore, если решение и факты не изменились; новый полный проход без оснований не нужен.
4. Оформи требования через [write-spec](../write-spec/SKILL.md). Если работа состоит из нескольких независимо проверяемых частей или зависит от порядка этапов, разбей её через [split-work](../split-work/SKILL.md); для одной задачи достаточно одного документа без формального разбиения. Это внутренние действия, а не дополнительные команды для пользователя.
5. Собери связный пакет: спецификацию, разбиение задач (если нужно), краткую схему модулей и интерфейсов, последовательность взаимодействий при необходимости, объём и исключения. Схема может быть краткой текстовой; для маленькой задачи не создавай искусственных модулей и набора документов.

Пакет готов, когда существенные вопросы решены или явно обозначены блокирующими. Получи согласование пакета до реализации, если пользователь ещё его не дал. После согласования и поручения выполнять используй implement. Изменённые поведение, объём или существенные интерфейсы согласуй снова.

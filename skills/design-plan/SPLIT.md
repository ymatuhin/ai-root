# Декомпозиция на задачи

Неясные требования отметь до разбиения.

1. Выдели небольшие законченные изменения с самостоятельной проверкой (узкий путь через нужные слои). Объединяй задачи одного модуля, если их нельзя проверить или выполнить отдельно.
2. Для широкого рефакторинга иди по цепочке: добавить совместимую форму → перенести потребителей проверяемыми частями → удалить старую форму. Если промежуточные состояния нельзя проверить отдельно, выдели общую задачу интеграции и не обещай зелёные проверки между шагами.
3. Для каждой задачи укажи идентификатор, результат, границы файлов/интерфейсов, зависимости по идентификаторам, критерии приёмки, проверки и общие файлы, мешающие параллельному выполнению.
4. Проверь отсутствие циклов и битых ссылок, покрытие всех требований, задачи без зависимостей и параллельные группы.

По умолчанию запиши разделом в `.scratch/<тема>/plan.md` (при передаче независимым исполнителям — в `.scratch/<тема>/issues/<NN>-<название>.md` в порядке зависимостей). Предложенное разбиение само по себе не разрешает реализацию.

# Выбор подхода

Если неясна цель пользователя, задай один вопрос и жди ответа (при большом числе развилок — через [grilling](../grilling/SKILL.md)); факты о коде и окружении собирай сам.

1. **Факты.** Проверь недостающее по первоисточникам (код, доки, спецификации). Для 2+ независимых вопросов или широкого поиска при доступности субагентов используй параллельных read-only субагентов (`факты`, `путь:строки`, `пробелы`).
2. **Сравнение.** Если разумный подход один — кратко обоснуй его фактами. Если есть разные по сути подходы (где живёт логика, что берём готовым, какую часть задачи закрываем), сравни их в таблице:
   - первый — **«Ничего не делать»** (что останется плохим, у кого и как часто);
   - второй — **самый простой вариант** для основных случаев (что с остальными: явная ошибка, отказ, ручной обход);
   - далее — только варианты, которые ты сам рекомендовал бы при конкретных условиях.

   | Подход | Суть | Что покрывает | Цена | Главный риск |
   | --- | --- | --- | --- | --- |
   | Ничего не делать | | | | |

3. **Проверка на избыточность.** Если рекомендуемый подход добавляет зависимости, абстракции или новые слои — проверь поиском по коду и докам, нет ли готового решения в проекте, платформе или стандартной библиотеке, и действительно ли сложность окупается.
4. **Итог.** Покажи рекомендацию с причинами, таблицу вариантов и оставшиеся неизвестные — без реализации. Если итог нужно перенести в другую сессию, сохрани его в `.scratch/YYYY-MM-DD-<тема>/decision.md`.

# Выбор подхода

1. Определи цель, ограничения и уже известные факты. Если для выбора не хватает фактов, собери их через [research](../research/SKILL.md). Независимые исследования можно выполнять параллельно при доступности субагентов, иначе последовательно.
2. Если есть существенно разные разумные подходы, сравни их через [brainstorm](../brainstorm/SKILL.md). Если найден один подход, кратко обоснуй его имеющимися фактами.
3. Если подход добавляет существенную сложность — новые зависимости, абстракции или этапы процесса, — проверь её через [doubt](../doubt/SKILL.md). Учти лишние части и неподтверждённые предположения; пересмотри рекомендацию при новых доказательствах.
4. Если после исследования и сравнения остаётся существенная неопределённость либо решение дорого переделывать (и этот спорный вопрос ещё не закрыт независимым проходом `doubt`), передай предварительную рекомендацию одному независимому read-only агенту по правилам среды. Передай цель, ограничения, факты, варианты и конкретный спорный вопрос; попроси проверить предположения, условия изменения выбора и более простой подход. Консультант работает без правок и своих субагентов. При недоступности субагентов явно проверь предположения сам и отметь ограничение независимости. Для понятной локальной задачи пропусти консультацию.
5. Покажи рекомендацию с причинами, рассмотренные альтернативы и оставшиеся неизвестные, если они есть. Результат — выбранное направление либо ясный выбор для пользователя, без реализации.

При продолжении с выбранным направлением используй [design-plan](../design-plan/SKILL.md). Если продолжение планируется в другой сессии, сохрани итог в `.scratch/<тема>/decision.md`.
